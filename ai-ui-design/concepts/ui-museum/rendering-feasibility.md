# 浏览器能否实现概念图的效果

2026-09-17。背景：用户看到 WASD 原型后认为与图片相差太远，询问 HTML 的表现能力。

## 判断

浏览器可以承载高质量 3D 展厅。HTML 负责页面载体，Three.js 等工具在 canvas 内绘制 3D，普通 HTML/CSS 负责文字、按钮和教学操作。能运行这些技术，并不等于自动得到概念图的画质。

Three.js 官方文档确认它提供基于物理的材质、法线/粗糙度贴图、环境光照和预先计算的光照贴图；物理材质还支持玻璃透射。复杂材质会增加渲染开销。

- [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)
- [MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

查阅方式：agent-reach 的 Jina Reader 请求超时，回退网页工具读取官方文档。以上是能力依据，不是当前项目画质已达标的证明。

## 两种目标的区别

| 目标 | 制作方式 | 边界 |
| --- | --- | --- |
| 保留概念图的固定构图，可点展品 | 高质量背景图与真实网页交互结合；可制作有限视差 | 能保留该视角的画面，但不能因此获得可任意行走的空间 |
| WASD 自由漫游且保持较高画质 | 完整建筑/展品/植物资产、细致材质、光照制作与浏览器性能优化 | 必须制作原图没有呈现的角度；画质、设备能力和资源大小需要实测 |

保留 WASD 是用户提出的探索方向，不应因为一次实现失败就擅自改成背景图方案。

## 本次失败的具体原因

对照原稿和 [浏览器截图](../../experiments/002-sunlit-museum/qa/desktop-initial.png)，现版本的光照偏平、材质缺少细节、建筑比例和场景层次改变，中央玻璃展品也没有保留原稿的设计。主要问题是场景制作和视觉还原不足，不能把它归因于 HTML 的能力上限。

## 建议的下一步

先做入口一小段空间和三个重点展品。把同机位画面、石材、玻璃、自然光与窗外层次做对，再检查附近移动视角；通过视觉检查后扩建其他展厅。静态建筑可以考虑预先计算复杂光照并保存为贴图，浏览器再处理需要实时变化的部分。具体效果与性能仍需验证。

这是一项实施建议，不承诺 AI 单次自动生成整套高保真 3D 资产，也不承诺把一张概念图无损变成任意视角的世界。
