# 实际踩坑记录

这里区分本次真正遇到的问题、已确认的原站行为，以及尚未验证的工程建议。不是把“可能存在的风险”写成发生过的事故。

## 1. 浏览器能显示的 HTML，构建器不一定接受

**观察**：Vite 首次构建报 `parse5 invalid-first-character-of-tag-name`。原站 Timeline 代码示例包含单字符字符串 `'<'`，直接放在 `<code>` 内，未编码成实体。

**处理**：在组装脚本中，仅对代码块的文本先解码已有实体，再编码 `<`、`>`、`&`。最终页面文字仍为 `'<'`，不把 `&lt;` 显示给读者。源文件原样保留在证据目录。

准确的前后 HTML 写法：

```html
<!-- 原始文本写法：浏览器容错，严格解析报错 -->
<code>.add('.ticker', { rotate: 360 }, '<');</code>
<!-- 构建输入：渲染/复制后的内容相同 -->
<code>.add('.ticker', { rotate: 360 }, '&lt;');</code>
```

**经验**：验证不仅是截图；源 HTML、DOM 文本、剪贴板文本是三个不同层次。

## 2. public 目录的模块，不等于 Vite 源码模块

**观察**：首页编译模块已保存在 `public/assets/js/`。从源码动态 `import()` 即使加 `@vite-ignore`，开发阶段仍出现带 `?import` 的请求，Vite 提示 public 文件不应从源码导入，页面未启动。

**处理**：通过创建 `<script type="module" src="/assets/js/home.js">` 引入整套原站模块树。Vite 只构建自己的适配入口，原站模块及相对 chunk 地址保持原样。

```js
// 本次失败的导入路径
const runtime = '/assets/js/home.js';
await import(/* @vite-ignore */ runtime);

// 本次验证通过的入口
const script = document.createElement('script');
script.type = 'module';
script.src = '/assets/js/home.js';
document.body.append(script);
```

**边界**：这是对“已编译网站本地复现”的处理。自己开发产品通常应直接以源码依赖的方式使用 npm 包，不应据此推导所有项目都要动态插入脚本。

## 3. 开发支持的语法，不一定符合构建 target

**观察**：适配入口的 top-level await 导致生产构建报错，默认目标包含不支持此语法的环境。

**处理**：将异步启动放进命名 `async function startReplica()`，保留错误处理；随后构建通过。没有为了一个入口无条件提高整个项目的兼容目标。

## 4. 地址替换要同时处理 URL 与 HTML 实体

**观察**：第一轮资源检查发现部分 GitHub 头像仍指向外网。下载清单里是 `&v=4`，赞助 HTML 片段里是 `&amp;v=4`，普通逐字替换漏掉了这些图片。

**处理**：同时替换原 URL 和 HTML 编码形式。再次检查浏览器资源清单，观察到的外域页面资源为零。外链导航仍指向作者网站或官方文档，不算资源热链。

**经验**：只搜索主 HTML 中的 `https://` 不够；异步返回的片段、CSS 字体、GLB 解码器与 JS chunk 都是依赖链。

## 5. 一个模型下载失败，整台装置就可能不完整

**观察**：108 个目标资源中，`module-shield-01.glb` 首次下载遇到 TLS EOF；107 个完成。

**处理**：只重试未完成文件，最终 108 个资源下载完成，原始资源合计 5,307,364 字节。记录 SHA-256；组装脚本发现下载清单中仍有失败时直接停止。

**经验**：先完成素材再实现，能把“资产缺失”和“场景写错”区分开。本次没有关闭 TLS 证书检查。

## 6. 滚动位置相同，也可能不是同一动画状态

**观察 A**：原站使用平滑同步。点击 Learn more 后，立即采集时 `scrollY` 还在 58/108；稍后稳定在 2160。第一次快速扫页的截图包含过渡帧。

**观察 B**：从页中重新加载旧标签再回到顶部，有一次原站的 Bundle size 浮层留在了首屏。将这张图与干净启动的本地页比较，会误判为复刻遗漏浮层。

**处理**：全面扫页用于发现内容；验收改用相同尺寸、相同进入路径、稳定后的状态。为排除滚动历史影响，额外打开干净原站标签建立对照。保存组合图，而不是只凭记忆比较两张分开的图。

**不确定性**：浮层残留的根因未完成源码级定位，不能断言就是浏览器滚动恢复导致；目前只确认它与旧标签重载/返回顶部的路径有关。

## 7. 不要把上游警告误报为新增问题，也不要把它藏起来

**观察**：本地出现 `THREE.BufferGeometry.computeBoundingSphere(): Computed radius is NaN`。原站新刷新后也出现了完全相同的警告。

**处理**：保留警告，不覆盖 `console.error`、不篡改几何计算。记录为继承的已知限制；本次检查的主场景仍正常渲染。

**尚未完成**：未定位产生非有限顶点的具体几何生成分支。真实产品应追踪第一次产生 NaN 的位置，而不是简单过滤日志。

## 8. 离线复刻不能误接真实业务

**实际实现**：移除原站统计和广告脚本，赞助接口改成本地快照；订阅表单在捕获阶段拦截，保留原视觉但显示“Local demo only — no email was sent or stored.”。文档类相对链接改成官方绝对地址，避免被 Vite 的 SPA 回退误显示成首页。

**验证范围**：浏览器验证表单反馈和资源来源；没有向原站提交邮箱。未复制站外业务页面。

## 9. 构建输出尺寸不是整个 3D 页面的下载尺寸

本地适配入口 gzip 只有约 1 KB，但 public 目录还有约 5.3 MB 原站资源。页面里显示的 27.13 KB 是原站对库模块体积的展示，不是此网站或本地项目全部下载量。不能拿它证明 3D 网站只有几十 KB。
