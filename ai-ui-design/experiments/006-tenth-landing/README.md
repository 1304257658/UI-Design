# 十分 Tenth 落地页 · 从一条随机字符串推导出的四个方向

这次的任务不是"随机抽一套视觉决策"，而是：**先拿到一条 144 位随机字符串，把它量一遍，
再从量出来的事实里长出四个互不靠近的设计方向。**

那条字符串本身不出现在任何一张设计稿里（由 `scripts/audit.mjs` 自动验证）。
它只负责提供限制条件 —— 就像真实项目里的品牌约束、法务约束、物理约束一样。

## 四个方向

| 案例 | 方向 | 认领的线索 | 文件 |
| --- | --- | --- | --- |
| A | 观测台 · Observatory | 144 = 12×12，一天 = 144 个十分钟格 | [cases/a.html](./cases/a.html) |
| B | 留白 · The Void | 全串唯一重复的是两个零；有 8 个字符一次都没出现 | [cases/b.html](./cases/b.html) |
| C | 中轴 · Axis | 正中心在索引 72；但镜像对称命中 0 处 | [cases/c.html](./cases/c.html) |
| D | 台账 · Ledger | 117 个字母里藏着 27 个数字（27 = 3³），十个数字一个不少 | [cases/d.html](./cases/d.html) |

**四个案例共用同一份受控内容**（见 [CONTENT-SPEC.md](./CONTENT-SPEC.md)）：同一个产品、逐字相同的文案、
相同的区块顺序、相同的交互要求。变的只有视觉语言和版式结构 —— 这样横向比较才成立。

推导过程（量了什么、为什么落到这四个方向）见 [DESIGN-ROLL.md](./DESIGN-ROLL.md)，
原始种子与生成命令见 [seed.txt](./seed.txt)。

四个案例文件本身也**双击即可打开**：单文件、零外部请求。

## 验证

```powershell
node scripts/audit.mjs            # 静态审计（含种子泄漏检查）
node scripts/check-js.mjs         # 内联 script 编译检查
node scripts/measure.mjs          # 无头 Chrome 实测 + 截图
```

`audit.mjs` 检查：标签闭合、花括号平衡、外部依赖、锚点落点、`aria-controls` 引用、
必需交互、逐字文案、十个区块的顺序、每个方向的**签名装置**、脆弱 `vw` 用法、820px 断点，
以及**种子泄漏** —— 随机串的整串与任意 8 位以上连续片段都不允许出现在设计文件里。

`check-js.mjs` 把每个案例的内联 `<script>` 抽出来做编译检查：语法错误会让表单、
价格切换、汉堡导航一起失灵，静态审计查不出来。

`measure.mjs` 用 Node 内置 WebSocket 直连无头 Chrome（不需要 npm 依赖），在
360 / 768 / 1024 / 1440 四个宽度下实测横向溢出并列出真正撑宽的元素，跑一遍
表单校验 / 价格切换 / 汉堡导航 / 手风琴，并输出整页截图。

## 每个案例都要过的验收项

- 单文件自包含，无任何外部请求（无 CDN、无外链字体、无远程图片）
- 邮箱表单内联校验，不用 `alert()`，错误提示带 `role="alert"`
- 月付 / 年付切换后，Pro 只显示一个数字（`¥40/月` 或 `¥32/月`，不同时出现）
- `<details>` 手风琴 FAQ
- ≤820px 汉堡导航，带 `aria-expanded` / `aria-controls`
- 锚点链接全部有对应 id
- 360 / 768 / 1024 / 1440px 无横向溢出
- 尊重 `prefers-reduced-motion`
- 设计稿里不出现随机字符串
