# 实现经验

2026-09-18，单次实验。审美仍待用户反馈。

## 面板必须共享坐标

CSS3DObject 承载真实 DOM 面板，WebGL 提供同尺寸背板；两者共享相机、位置、缩放和旋转。接近侧面时淡出文字，保留细边，回转时恢复同一个 DOM。CSS3D 和 WebGL 深度并不天然统一，本实验通过位置和消隐区间约束交叠。

## 进度决定状态

位姿、章节、文字长度与粒子位置均由进度重算，不累加对象每帧位移。粒子种子由索引确定。自动播放只是推进相同进度，手动滚轮或点选模块会暂停。这样才可以反向滚动和按同一进度比较截图。

## 原生滚动和自定义外观分开

内部 overflow 保留原生滚动，用 overscroll-behavior-y: contain 阻止边界传播，隐藏 scrollbar 外观后使用可键盘控制的 range input。内部滚动和滑块都驱动同一个时间轴，没有全局拦截所有 wheel。

实测：内部滚动后外层 scrollY 仍为 229；移到外部滚动后页面到 688，内部 scrollTop 保持 3806。内部到终点再滚动，外层仍为 229。原始数据见 evidence/interaction-checks.json。

## 几何排列不能伪造架构

工具返回的初始路线直接连到模型适配组，视觉上省略 Session。已改成工具 → 结果记录 → 下一步请求 → 模型。Cordis 贯穿系统，不能画成单次请求的一道串行关卡。平板、电路和二进制字符均为视觉隐喻，不代表实际硬件或模型内部。

## 手机需要重新组织阅读

实际检查发现 Cordis 标签裁切、控制器位于长说明之后。修复为按标签宽度限制坐标，手机顺序改成场景 → 控制器 → 说明。最终面板缩小后文字偏小，因此说明区另提供正常字号答案。支持 hover、focus 和点击；减少动态效果偏好默认进入静态架构。

## 真实环境差异

npm 第一次安装遇到缓存目录权限问题，使用已授权的依赖安装流程后成功。内置浏览器原生 Fullscreen API 未进入，实际验证的是全视口 fallback 进出，不能混淆。Three.js 占主要打包体积，约 529 kB JS 产生默认 chunk 提示但不阻止构建。仅在输入、播放和尺寸变化时更新画面，页面离开时释放几何、材质、纹理和渲染器。

## 本次形成的方法

先固定源码与职责，再划分视觉模块；把静态依赖和动态路径分别表达；完整展开和答案终点保留阅读状态；跨尺寸截图用归一化进度对齐。以上仅完成一次实验验证，不等于已证明可普遍产生优秀设计。


## 用户否定 V1 后的视觉修订

功能正确不等于设计成立。六个相似矩形加上滚动位移，无法自动获得一个值得拆解的产品形象。V2 先改变轮廓：中央端口、控制盘、鳍片；两侧叠页、存储柱与工具接口。再补倒角、螺钉和刻线。几何外形仍是教学隐喻，不能据此推断真实硬件组成。

金属需要可反射的环境。使用 Three.js 自带 RoomEnvironment 经 PMREM 生成环境图，MeshPhysicalMaterial 提供粗糙度和 clearcoat。色彩管理顺序为线性 HDR 场景 → RenderPass → UnrealBloomPass → OutputPass。场景背景明确设置 scene.background，避免依赖后处理过程中会改变的 clearColor。发光过强会淹没倒角和刻度，不能把亮度当成质感。

工作台初始大小按相机可视宽度限制。持续说明放在场景下方，源码职责通过 hover、focus、click 按需打开；手机说明继续正常排版。最终答案副本放在控制条之后，避免挤走回放入口。

截图也有时序：JS 状态更新不证明合成帧已经完成。首次快速截图出现 100% 文件仍展示 88% 的问题；等待两个绘制帧后重采。还发现把调试属性命名为 data-chapter 会污染现有章节选择器，改为 data-scene-chapter。两类问题均应从实际截图与 DOM 对照发现，不能只检查 JSON。

代价是更多几何与后处理，构建 JS 约 586 kB / gzip 156 kB。DPR 上限 1.5，输入变化时才渲染；释放 composer passes、render targets、环境图等资源。没有进行帧率基准，不承诺低端 GPU 达到 60 fps。


## V3：信息表达先于物体造型

用户原本期望流程图，机械拆解只是实现者的解释。继续给物体添加材质没有解决信息容量问题。本轮改为 DOM 节点与 SVG 路径：节点标题、模块名和职责始终可读，细节说明位于图后。装饰并不构成解释，隐喻必须服从学习目标。

手机不能将桌面大图等比缩到四分之一。默认阅读版转成纵向分组，并为各节点保留明确关系文字。可选动画版保留横向查看；两种模式都共享同一职责数据与时间轴。

静态图优先，演示按需进入。切换模式时，必须先保存用户拖动的目标进度，再执行改变布局的 setStatic；否则模式函数重写滑块值会让用户的第一次拖动失效。

V2 WebGL 几何不再加载，当前构建使用 HTML/CSS/SVG，JS 约 25 kB。这里的减小来自技术需求改变，不表示所有 3D 展示都应该改成流程图。


## 2026-09-19：同一个对象贯穿换景

用户要求工作台折叠后的横线继续承担图内 UI 的位置。删除独立 Web UI 卡片，将 prompt 连线起点和响应终点接到横线；横线仍可点开 UI 的源码说明。面板折叠时，位置与最终宽度同时收敛到线的位置；在接近 90 度时交接可见性，避免先消失再生成另一个节点。

工作台处于浅色空间，流程图进入深蓝色运行时环境。背景、边框、节点、文字、说明与控制区共享同一环境混合变量，随进度确定性计算，避免靠 CSS 时间动画导致倒放不同步。横线先出现，流程图随后展开；返回时方向相反。手机动画模式缩短横线宽度，返回路径端点也同步更新。
